# 「那不是紀律問題，是缺一項測試」——這句話到底在說什麼

**日期**：2026-09-04　**工作項**：**PROVE**（小，不在 PLAN 路線圖上）
**狀態**：完成（本檔案在開工的第一件事就建立，見 `dispatches/README.md`）

---

## 提示詞（逐字）

您在回覆中的 "一、第3點" 有一句話這樣說： "那不是紀律問題，是缺一項測試。"  請更清楚的說明這句話的意思，不然聽起來很像人會用的一些話術，例如 "這不是問題 ，是一個特色"。

### 那句話出現在哪裡

上一輪（2c+GUARDS）回答老師的問題「若實作皆由 AI 進行、人類沒有手動改 code，
第 2、3 點的問題是否就不會發生」。第 3 點是「有人寫了新的 generator 但忘了在
`app/generator/__init__.py` 加 import，於是沒有任何測試碰得到它」。

---

## 回覆

### 一、先承認老師這個懷疑是對的方向

「這不是問題，是一個特色」之所以是話術，關鍵不在它講得對不對，而在
**它把一句可以被檢查的話換成一句不能被檢查的話**。原本「這裡有一個問題」
是可以驗的（給出重現步驟就結案），換成「這是特色」之後就沒有東西可以驗了
——沒有任何實驗能證明它錯。

所以「那不是紀律問題，是缺一項測試」要不要算話術，**只有一個判準**：

> 這兩個標籤，會不會導出**不一樣而且可以驗證的**下一步？

如果兩邊導出的下一步一樣，那我只是換了一個好聽的說法；
如果不一樣，而且其中一邊當場可以驗，那它就是一個具體的主張。

### 二、兩個標籤導出的下一步確實不一樣

| | 說它是「紀律問題」 | 說它是「缺一項測試」 |
|---|---|---|
| 補救動作 | 「下次記得」、寫進檢查清單 | 寫出一個具體的檔案改動 |
| 補救有沒有效，怎麼知道 | **沒有辦法知道**。要等下一次有人忘記才會發現沒效，而那可能是三個月後 | **當場可以知道**：故意做出那個錯，看它會不會紅 |
| 失效時會發生什麼 | **什麼都不會發生**。忘了加 import 的症狀是「全部綠燈，而那個檔案是死的」——沒有人會被告知 | 紅燈，附一句話指到 `app/generator/__init__.py` |

第二列是重點。**紀律要能運作，前提是失效的時候有人會知道。**
「忘了加一行 import」這個錯的性質剛好是：失效時**測試全綠、選單看起來正常、
沒有任何錯誤訊息**。在一個不會給回饋的地方要求紀律，等於要求人不出錯——
那不是紀律，那是運氣。

⚠️ 這正是 `CLAUDE.md` 裡本來就寫著的三層防護，只是上一輪講得太快：

1. **人記得的慣例**——最弱，因為失效是靜默的；
2. **指令印出來的提醒**（`git-safe-commit.sh` 會印）——中間，至少會被看到；
3. **一項測試**——唯一一層不依賴記憶的。

「那不是紀律問題」準確的意思是：**紀律是錯的那一層**，不是「沒有人有疏忽」。

### 三、也要說清楚那句話裡該讓步的部分

⛔ 上一輪那句話有一個地方確實太漂亮了：**忘記加那一行 import，就是有人疏忽了。**
如果「不是紀律問題」被讀成「沒有人有錯」，那就是不誠實。

準確的說法是兩句，缺一不可：

- 有人疏忽了（**是**紀律的問題）；
- 而把補救放在紀律那一層**沒有用**，因為那一層在這個錯上收不到回饋
  （**所以要**放到第三層）。

上一輪只講了後面那句。

### 四、⛔ 但光是解釋，仍然只是換一種說法。所以這一輪把它拿去驗了

那句話做了一個**可以被否證的預測**：

> 如果補上的那項測試真的守得住，那麼**故意把它弄壞，就必須看到紅燈**。
> 如果弄壞了還是綠的，那句話就是話術。

而一驗就發現：**上一輪的我自己用了雙重標準。**

- 附錄 C 的符號正規式，我有寫突變測試
  （`test_that_check_would_have_caught_the_old_spelling`——把 v0.37 之前
  真的出現過的三個舊字串餵進去，斷言它們會被抓到）；
- **D70 的孤兒檢查，我沒有寫。** 我只是宣稱它有效。

於是實測。把孤兒檢查裡掃檔案的那一行 `root.rglob("*.py")`（遞迴掃所有子目錄）
改成 `root.glob("*.py")`（只掃第一層），這是一個很容易發生的手誤：

```
tests/test_web.py::test_no_python_file_under_app_is_an_orphan   PASSED
```

⛔ **綠的。** 也就是說：那項檢查可以在完全不被察覺的情況下退化成一項
**永遠不會紅的檢查**——測試總數不變（還是 1197 項）、CI 顏色不變、
沒有任何東西會抱怨。而真正的孤兒（`app/generator/ode/` 底下那種，
也就是唯一會真的發生的位置）從此不再被抓到。

**那一格才是這句話真正的意思**：連「這裡有一項測試」本身，都不能靠人相信，
要靠另一項測試。

### 五、這一輪做的事

1. 把判斷邏輯從測試裡抽成一個函式 `_orphans_under(root, loaded)`
   ——抽出來的唯一理由，是讓它可以被餵資料、因而可以被證明會紅。
2. 新增 **`test_the_orphan_check_actually_goes_red`**：用 `tmp_path` 造一棵
   合成的樹（`app/main.py`、`app/generator/base.py`、
   `app/generator/ode/forgotten.py`），三個案例對應三種寫壞的方式——

   | 案例 | 擋住的是 |
   |---|---|
   | 三個檔案都「載入了」→ 不得報警 | 誤報（會誤報的檢查沒人敢留著） |
   | 巢狀那一個沒載入 → 必須抓到 | **`rglob` 被寫成 `glob`**（上面那個實測） |
   | 那個孤兒含 `@register(` → 必須多印那句指路的提示 | 提示本身爛掉 |

3. ⚠️ **刻意用合成的樹，不拿真的 `app/`**。v0.36 已經踩過一次：
   拿真實的相依地圖去驗一項檢查，環境的變動讓它時紅時綠——
   **一項會自己閃爍的測試比沒有測試更糟，它會訓練人去忽略紅燈。**
4. 把這件事寫成往後的通則（`CLAUDE.md` 新增一節、`PLAN.md` 記為 **D71**）：
   **凡是「正常情況下永遠是綠」的守門測試，都要配一項突變測試**；
   否則它只證明了「今天沒事」，沒有證明「有事的時候它會說」。

### 六、驗證

兩個突變，各驗一次（改完就還原）：

| 故意做的錯 | 真的那項孤兒檢查 | 新的突變測試 |
|---|---|---|
| `rglob("*.py")` → `glob("*.py")` | ⛔ **綠**（抓不到） | ✅ 紅，訊息寫「最可能的原因是掃描只走了第一層」 |
| `on_disk - loaded` 方向寫反 | ✅ 紅（`ValueError`） | ✅ 紅 |

第一列就是這一輪存在的理由。
