**日期**：2026-09-16　**工作項**：**FIX-D82**（修 v0.45 造成的一次真實故障）
**狀態**：程式碼與測試完成；⚠️ **牆鐘紀錄與相依地圖尚未更新**（見文末）

---

## 提示詞（逐字）

> 我發現 convolution 那個網頁壞了，沒有聲音沒有波形按鈕也無反應。我現在在通勤，電腦沒開機，但上個版本有 push 到 GitHub repo，能否從 GitHub 那個版本協助我檢查問題？

---

## 一、⛔ 先講結論：GitHub 上那一版是好的

從 `https://github.com/wangc86/engmath-practice` clone 一份（HEAD 是
`d4659ea`，也就是 v0.45 的三個 commit 都在上面），在沙箱裡起 uvicorn，
用**真的 Chromium**（Playwright，非無頭 shell）開那一頁、按下 Play the voice：

```
200 /static/demos/samples/speech-welcome.wav
status: "Sound is running at 44100 Hz, the rate your device chose.
         Playing the original recording."
```

⛔ **程式碼沒有問題。** 所以要找的不是「哪一行寫錯」，是「為什麼在你的瀏覽器裡
它是死的」。

## 二、三個症狀是同一個原因

老師給的三個症狀——沒有聲音、沒有波形、按鈕沒有反應——看起來像三個問題。
⚠️ **其中「沒有波形」是那個關鍵線索**：畫圖不需要音訊，除非畫圖用的資料
要先解碼，而解碼是 `AudioContext` 的方法。三個一起壞，只有一種解釋：

> **進入點模組在求值階段就丟了例外，整支當場死掉。**

於是 `render()` 從來沒有被呼叫（三張圖空白）、檔尾那一段 `addEventListener`
從來沒有跑到（按鈕全死）、`audio` 沒有被建立（沒有聲音）。

## 三、成因：**新的 HTML 配上舊的 JS**

⛔ 實測 `/static/` 回的標頭：

```
last-modified: Wed, 16 Sep 2026 00:25:36 GMT
etag: "e63fbc27240d4948c5879d94b6361180"
（沒有 Cache-Control）
```

**沒有 `Cache-Control` 的意思不是「不要快取」，是「你自己猜」**——HTTP 允許
瀏覽器在沒有明示到期時間時用 heuristic freshness（常見作法是「距離
last-modified 的時間的 10%」）自己決定一份檔案還新不新。也就是說：

> ⚠️ 一般的重新整理，瀏覽器**可以合法地完全不問伺服器**，
> 直接拿出它手上那一份 `convolution.js`。

而展示頁的 HTML 是動態產生的、每一次都是新的。兩者的快取壽命**各走各的**，
於是出現「新的 HTML（沒有 Start sound 按鈕）＋ 舊的 `convolution.js`
（仍然傳 `onToggle`）」。**那正好是 D80 那個一致性檢查要抓的情況**，
它照設計丟了例外。

**在真的瀏覽器裡重現過，兩種混法都試了**：

| 情境 | 例外 | 三張圖的像素 | 按 Play | 畫面上的訊息 |
|---|---|---|---|---|
| 新 HTML + 舊 `convolution.js` | `createShell: onToggle was given but the page has no Start/Stop button` | 0 / 0 / 0 | 沒有反應 | **無** |
| 新 HTML + 舊 `lib/shell.js` | `Cannot read properties of null (reading 'addEventListener')` | 0 / 0 / 0 | 沒有反應 | **無** |
| 乾淨的 `d4659ea` | 無 | 1436 / 3473 / 1436 | 正常播放 | 無（正常） |

⛔ **和老師描述的一字不差。**

## 四、⛔ 真正該記下來的不是快取，是「它壞得沒有聲音」

D80 那個 `throw` **本身是對的**——它存在的理由正是「不一致不能靜默」。
⚠️ **錯的是它沒有人聽。** 一個為了讓錯誤不被忽略而設的 throw，在一個
沒有全域錯誤監聽器的頁面上，效果恰好相反：**它讓整頁安靜地死掉**。

這是硬規則 4 的一個我沒有想到的形式。規則 4 一直被理解成「失敗要顯示在畫面上」，
而這一次失敗的是**放置那句訊息的那段程式碼自己**。

## 五、兩個缺口，各補一個

**(a) `lib/crash-notice.js` + `_crash_notice.html`**（六頁都掛上）

⚠️ **獨立的進入點**，與 D45(6) 完全同一個論證：它要報的失敗，正好會讓那個
檔案掛掉。⛔ **而且必須排在展示模組的前面**——`<script type="module">` 依
文件順序求值，排在後面等於監聽器還沒掛上去；**那個錯誤不會有任何症狀**，
直到真的有人壞掉的那一天，而那天它剛好不會說話。有一項測試盯著順序。

訊息第一句叫學生做硬重新整理（到目前為止唯一真的發生過的成因就是它），
並**把原始的錯誤訊息原樣印出來**：那是老師或助教唯一拿得到的線索，
而學生有辦法把螢幕上的一行字念出來。⛔ 不叫學生去開 devtools。

**(b) `RevalidatingStaticFiles`**：每一個靜態檔案送 `Cache-Control: no-cache`。

⚠️ **不是 `no-store`**——檔案照樣存得住，只是每次都要先問一次；配上既有的
`etag`，答案通常是一個 304（零位元組），而這個系統跑在 localhost 上。
⛔ **刻意不用 `?v=…` 的 query**：那只管得到範本裡寫得出名字的那幾個檔案，
而真正咬人的是 `import` 進去的那一層（`lib/*.js`）——它們的網址寫在 JS 裡，
範本碰不到。

## 六、測試 1318 → 1340（+22），三項做過突變驗證

| 突變 | 結果 |
|---|---|
| 拿掉 `Cache-Control` 那一行 | 紅 |
| 把監聽器排到展示模組後面 | 紅 |

## 七、⚠️ 這一輪最該記住的一句話

> **1318 項全綠，而那一頁在真的瀏覽器裡是死的。**

假 DOM 的 smoke harness 連 `AudioContext` 都刻意沒有（那是它原本的設計，
用來驗「不支援 Web Audio 時有沒有把話說出來」），所以它從來不會執行
「按下 Play → 開音訊 → 解碼 → 播放」這條路，也不會執行任何一行
「模組真的被瀏覽器求值」時才會發生的事。

⛔ **這是 2S7（跨瀏覽器實測）不是可選項的第一個真實證據。**
⚠️ 順帶一提：這一次的實測是在沙箱裡用 Playwright 驅動真的 Chromium 做的
——**那條路在這個專案裡之前沒有用過**，而它抓到了 1340 項測試抓不到的東西。
值得考慮把它變成一個可以重跑的東西，但那是另一輪的事，這裡只把它記下來。

## 八、⚠️ 這一輪的分工，以及它本身是一個值得記的事實

**⛔ 這一輪的程式碼是在沙箱裡寫出來、在沙箱裡驗證的，老師的機器當時是關的。**
順序是這樣：

1. 老師在通勤中回報故障，只給得出症狀與一個 GitHub 網址；
2. 沙箱 `git clone` 那個 repo，起 uvicorn，用 **Playwright 驅動真的 Chromium**
   重現——⛔ 第一件確定的事是「乾淨的 `d4659ea` 是好的」，也就是**要找的不是
   程式碼的錯**；
3. 把兩種「新 HTML + 舊 JS」的混法各造一次，症狀與老師的描述一字不差；
4. 修正與測試都在沙箱裡寫完、突變驗證也在沙箱裡做完，產出一份 patch；
5. ⚠️ **老師先在自己的 Chrome 上按了 Ctrl+Shift+R，確認頁面恢復正常**
   ——那一步才是真正證實成因的那一步，沙箱做不到；
6. 機器上線後套用 patch、在**老師的機器上**重跑全套。

⚠️ **`turnaround.py start` 是在第 6 步才跑的**，所以 `TURNAROUND.csv` 這一列的
牆鐘時間**只涵蓋收尾**，不含第 1–4 步在沙箱裡的時間。
⛔ 那一列因此**不能拿來估「這種修正要花多久」**，備註裡寫明了。
（`.turnaround-current.json` 不進版控，一輪不能在一台機器 start、另一台
finish——這是 D77 那一輪就寫下的限制，這次是它第一次真的咬到。）

**全套在老師的機器上跑過**：十四批 generator 加上其餘七個測試檔，
1340 項全部通過。
