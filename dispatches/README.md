# `dispatches/` — 每一輪派送的原始提示詞

> **這個目錄從 v0.29（2026-09-02）開始，而它開始得太晚了。**
> 前面約二十輪的原始提示詞**沒有留下來**，理由與補救見
> `../COLLABORATION-NOTES.md`。這一段話是這個目錄存在的主要理由：
> 讓同樣的事不要再發生一次。

## 這裡放什麼

一輪 = 一個檔案。檔名格式：

```
YYYY-MM-DD-<版本或工作項>-<三五個字的主題>.md
```

例如 `2026-09-01-v0.28-week-gating.md`。

每個檔案至少要有兩節：

1. **提示詞（逐字）** —— 老師送出的那段文字，**一個字都不要改**。
   排版、錯字、中英夾雜全部原樣保留。改過的提示詞就不是提示詞了，
   它是一份事後整理，而那兩件事的用途完全不同。
2. **回覆（逐字或摘要）** —— AI 交付時的那份回報。太長的話可以摘要，
   但**摘要必須標示為摘要**，而且不得省略「踩到的坑」與
   「還不夠穩的地方」那兩段——那兩段是這份紀錄裡最有價值的部分。

可選的第三節：**事後的實際結果**（哪些預測成真、哪些沒有）。

## 為什麼要留

三個用途，由近而遠：

1. **接手的人看得懂為什麼。** `PLAN.md` 記的是**決定**，這裡記的是
   **要求**——而兩者常常不一樣。看得到原始要求，才看得出某個決定是
   老師指定的、還是 AI 自己判斷的。
2. **人機協作的教學素材。** 這門課的學生自己也在用 AI 開發；
   一份「這樣問 → 得到這樣的結果」的真實紀錄，比任何提示詞技巧的
   投影片都具體。
3. **回報可不可信，事後查得到。** CLAUDE.md 的第九條硬規則要求回報必須
   是真的，而那一條**沒有任何測試守得住**。留著提示詞與回報，
   至少讓「當初說的」與「後來發生的」對得起來。

## 一個**新工作階段**的第一個提示詞

換機器、換 AI、或學生接手時，第一個提示詞不該是一個實作任務，而是一次
**交接驗收**——證明環境跑得起來、證明接手的人讀懂了規則，然後才動程式碼。

可以直接複製的樣板在 **[`TEMPLATE-first-session.md`](TEMPLATE-first-session.md)**。

## 開工時的第一件事

與 `scripts/turnaround.py start` 同一個時機——**在讀 PLAN 之前**：

```bash
# 1. 把提示詞原文貼進去（heredoc 的引號要加，否則 $ 會被 shell 吃掉）
cat > dispatches/$(date +%F)-<主題>.md <<'PROMPT'
# <主題>

## 提示詞（逐字）

<在這裡貼上>
PROMPT

# 2. 然後才是計時
python scripts/turnaround.py start <任務編號> --estimate <人週>
```

⚠️ **這件事沒有測試守得住，也不可能有**——沒有人知道「這一輪應該要有一個
檔案」。它與第九條硬規則同一類：**唯一的執行機制就是把理由講到讓人不想
繞過**。所以理由寫在上面那三點，而不是只寫「請記得留存」。
