## 提示詞（逐字）

> 我意識到 convolution demo 那一頁我先前只請您做出一半的功能，也就是 "給定同一個輸入訊號，做出在不同系統的輸出"。我想請您也做出如下（另一半）的功能："給定不同的輸入訊號，做出在同一個系統的不同輸出。" 也就是說，這一半的功能之目的在展示給學生看 "如果已知一個系統的 unit impulse response，則若想要瞭解該系統在給定不同輸入時會如何反應，只須知道那個新輸入的函數表示式，接著計算 convolution 即可推論系統輸出，不須真的在該系統做實際 (physical) 的實驗。這對於判斷系統在應對不同可能的輸入時是很有效率的策略。"（…）第二個請播放這則經典的古典音樂 "Bach BWV 846 Prelude in C major" ，只需要簡單的聽起來類似 MIDI 那樣產生純粹每個音的頻率的版本。

**問過的一件事**（`AskUserQuestion`）：長度。老師的回答是
**「在現有功能下，若學生可以中途中斷播放，那就放全部 35 小節，否則就放前 8 小節。我覺得不須比較或對齊兩個輸入的長度。」**
——頁面上有一顆 `Stop`，`stopPlayback()` 真的會把 buffer source 停掉，
所以按老師的規則走**全曲**。

## 一、⛔ 這一段的重點不是多一首曲子，是「第二個輸入不是錄音」

老師那段話的關鍵是「**只須知道那個新輸入的函數表示式**」。
⚠️ 如果第二個輸入也是一份 wav，這句話在畫面上是看不見的——兩個輸入都是
「從某處錄來的東西」，學生只會覺得換了一首背景音樂。

所以：**BWV 846 沒有對應的音檔**。整段音樂在瀏覽器裡由 `bachPrelude()`
算出來，每個音就是一項

$$A\sin(2\pi f t)\,e^{-t/\tau}$$

全部相加。⛔ **沒有人去那個隧道裡彈過這首曲子**，而學生聽得到它在那裡的
樣子——那正是老師要展示的那句話。

⚠️ 兩個輸入的**不對稱是資產，不是要抹平的東西**：`inputAt()` 裡語音那一支
要 `await` 一個 `fetch` 再解碼，Bach 那一支只是一個迴圈。程式碼裡留了一段
註解說明那個不對稱**刻意不包成同一個樣子**。

## 二、音高從哪裡來：⛔ 不是看著樂譜抄的

1. 從 **`music21` 內建曲庫的 `bach/bwv846`**（機器可讀的 MusicXML）用程式抽出來。
2. **重建再逐音比對**：前 31 小節必須完全符合 `n1 n2 n3 n4 n5 n3 n4 n5`
   這個音型；右手那 12 個十六分音符必須恰好是 n3 n4 n5 重複四次；
   左手必須恰好只有兩個音高。**31 小節全部通過，一小節例外都沒有。**
3. 最後三小節（收尾）不是那個音型，所以**逐音列出**（43 個事件）。
4. 把寫進 `signal.js` 的數字**再抽回來**，和來源算同一個 SHA 比對
   （`4faaf7a846b734d9`）——⛔ 搬運的過程一個音都沒有改。

### ⚠️ 兩件我**沒有**做到的事，寫出來而不是略過

- **與老師上傳的樂譜只核對了一處**：第 21–23 小節的低音 F2 / F♯2 / A♭2
  （樂譜上看得到那個升記號與降記號），兩邊一致。
- ⛔ **兩份的小節總數不一樣**——這裡用的是 34 小節，老師那份（Clint S. Mers
  2000 年的打譜）看起來是 35 或 36。這首曲子的版本差異是眾所周知的
  （最有名的是後人加上去的「Schwencke 小節」），**而我沒有去查清楚差別在哪裡**。
  用 music21 那一份的理由只有一個：它是機器可讀的，我驗證得了。

## 三、最有價值的那一項測試，與音表**完全無關**

其餘幾項都在問「表裡寫了什麼」。⛔ 那些項目有一個共同的盲點：
**合成器接錯線的時候，音表還是對的。**

所以多了一項：把合成出來的**第一秒**做一次 FFT，看最強的幾根譜線落在哪裡。
第一小節只有五個音，所以那幾根線必須落在
261.6 / 329.6 / 392.0 / 523.3 / 659.3 Hz 附近。實測：

```
topPeaks  261.5  329.6  522.9  659.2  391.1  393.3  327.4  525.1
```

（G4 響得最短，譜峰最寬，分裂到相鄰兩格——所以容忍度給到 3 Hz。）

**兩個突變實測都會紅**：

| 突變 | 誰抓到 |
|---|---|
| MIDI → Hz 的指數寫反（`69 - midi`） | ⛔ **只有頻譜那一項**（A4 仍然是 440，音表完全正確） |
| 音型後三個寫成 `n1 n2 n3` | 逐項比對那一項（⚠️ 聽起來仍然是同一個和弦） |
| 第一小節少一個音 | 兩項（合成器會讀到 `undefined` → 整段 NaN → 那一小節是靜音） |

## 四、順手補的一個規則 4 的洞

實測（`node`，沙箱）：

```
產生 Bach 3323250 點（75.36 秒）: 1281 ms
房間 h（隧道）83790 點:             18 ms
摺積 y 3407039 點:                3140 ms
```

⛔ 第一次按下去要等約 4.4 秒，而 FFT 跑在主執行緒上——**畫面是不動的**。
原本就有一句「Working out the convolution…」的提示，⚠️ **但它永遠來不及畫
出來**：`scheduleRender()` 排的是一個 rAF 回呼，而那個回呼與底下的同步運算
在同一格裡。改成算之前先讓出兩個 frame（`yieldToPaint()`），
在真的 Chromium 裡實測那句話會在畫面上出現：

```
t≈0ms    Sound has not started. …
t≈200ms  Working out the convolution for the Bach prelude in this room — …
t≈400ms  Playing the Bach prelude on its own.
```

⚠️ 另外 `ensureRendered()` 的快取鍵補上了輸入：v0.47 之前只有房間與取樣率，
**換了輸入而鍵不變的症狀是「選了 Bach 卻還是聽到語音」，而波形也會跟著是舊的
——連「看起來怪怪的」都不會發生。**
