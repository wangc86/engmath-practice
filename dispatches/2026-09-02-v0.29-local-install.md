## 提示詞（逐字，第一段）

> 我思考過後，決定做一個大改變：我決定改為不要用單一網站讓學生登入，而是將這個系統推到我的 github 上，開放給學生自行下載安裝。原因有二：1. 架站比我想像複雜且有資安風險，且學校防火牆的配置會是必要但不便的額外工作；2. 這學期修課的學生都是資工系學生，會使用 python 及基本的 linux/macOS command-line interface，我把系統開放給他們自己用，也可以讓他們體驗如何透過 AI 人機協作來開發這類系統。
> 我預期讓學生自己安裝這個系統使用，介面一樣也是讓學生透過開瀏覽器的方式來存取系統的功能，只是變成讓他們自己存取自己本地端的系統服務。請分別擬一個 Linux 的安裝使用說明及 macOS 的安裝使用說明檔案。
> 現在改成這樣，就不需由系統端紀錄或回報使用者的用量等任何資訊，我會再另外想辦法評估（例如讓學生錄影他們的操作）。請依據現在這樣的變動，刪除掉不必要的規劃，以及刪除掉不必要的測試項目。
> 上述都完成後，請將這整個 dispatch 的專案匯出成一個 self-contained 的壓縮檔，未來我會再另外用 Claude Cowork 繼續接下來的開發，且也讓有興趣的學生可以用他們自己的 AI 繼續。這樣關鍵是否是你要把 MD 檔寫得夠完整？此外，這個 self-contained 的壓縮檔，是否也能以文件或任何易於閱讀的形式，記錄下這個專案從頭到目前的所有 dispatch 提示詞及您的回覆？這樣我也能將它作為一個人機協作的學習筆記。

## AI 的回應：一件做不到的事，與兩個問題

> ⚠️ 這一段是這份紀錄裡最重要的部分之一，因為它示範了一個具體的協作動作：
> **在動手之前把「做不到的部分」講清楚，而不是交付一份看起來完整、
> 實際上缺一角的東西。**

摘要：

1. **先前 dispatch 的原始提示詞拿不到。** 每一輪 dispatch 是獨立的工作階段，
   AI 只看得到當輪的對話；先前的提示詞在應用程式自己的目錄裡，不在可存取
   的資料夾範圍內（實際試過）。因此「所有 dispatch 提示詞及回覆」這一項
   只能做到一部分。可行的替代是 **1+2+3**：本輪逐字收錄 ＋ 從 PLAN／git／
   TURNAROUND 重建的專案史（明白標示為重建）＋ 建立 `dispatches/` 慣例
   讓往後不再遺失。
2. **兩份安裝說明用什麼語言？**（繁中／英文／中英各一）
3. 附上打算砍掉的完整清單請老師逐項確認，並先打了 git tag `hosted-v1`
   讓每一項都取得回來。
4. **PLAN.md 建議「標記為已捨棄」而不是實體刪除**，這一點與老師說的
   「刪除掉不必要的規劃」有出入，所以主動提出來讓老師裁決。
