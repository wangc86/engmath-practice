## 回覆

**新增了 `MOVING-MACHINES.md`，而寫這份文件的過程本身抓到一個安靜的錯**（D77）。

### 一、⛔ 先講那個錯，因為它正好是您這個問題會踩到的第一個坑

`MOVING-MACHINES.md` 本來要寫的一句話是：

> 「在新機器上第一次跑會全部判定過期 → 全跑。**這條規則從機制裡長出來，不靠人記得。**」

那句話從 v0.36（D68）就寫在 `PLAN.md` 與 `CLAUDE.md` 裡。
⛔ **我這一次沒有直接抄它，而是去驗了一次**——在沙箱裡 `git clone` 一份、
提交成乾淨的工作區、跑 `scripts/test_deps.py select`：

```
沒有任何變更。
```

**它說不必跑。** 正確答案是「八個測試檔全部要跑，約 1690 秒」。

原因：`select` 的 CLI **先問 git「有沒有未提交的變更」**，沒有就印那句話然後
`return`——⛔ **而那一行在「地圖過期的也要跑」被執行到之前**。
機制長出來了，但 CLI 在它前面就把話講完了。

⚠️ **失敗的方向是最壞的那一個**：它說「不必跑」，畫面上什麼都沒有紅，
於是在一台新機器上照著它做，等於在一份**每條相依都對不上**的地圖上開始改程式。
⚠️ `run` 子指令沒有這個問題（它呼叫的是 `select(...)` 本身），
所以症狀只出現在「先問一下要跑什麼」那條路上——**而那正是人會走的那條**。

修好了，並補上一項用**合成地圖**的測試把這個性質釘住。
修好之後在同一份新 clone 上實測，輸出是八個檔案、1688.5 秒。

### 二、換機器要做的事（完整版在新文件裡）

**0. 舊機器上先確認沒有東西還沒推上去。**
✅ 查過了：`git reflog show origin/main` 顯示您每一輪之後都有 push，
最後一次 `13:25:52 +0800` 對到最後一個 commit。⚠️ 但那是**當下的事實，不是一條性質**，
所以文件裡仍然要求換機器前跑那三個檢查指令。

**1. 新機器上要有四樣東西**：Python ≥ 3.10、git、**Node.js**、一把新的 SSH 金鑰。

**2. ⛔ Node.js 那一項要單獨講，因為它的失敗方式是靜默的。**
沒有 `node` 的時候，`tests/test_dsp_js.py` **整份 405 項**（模組層的 `pytestmark`）
加上 KaTeX 那 1 項會被跳過。⚠️ **它們是 `skipped`，不是 `failed`** ——
全套會印 `889 passed, 406 skipped` 而不是 `1295 passed`，
**而 889 個綠燈看起來非常安全**。這是 `CLAUDE.md` 那句
「守著不存在的東西的綠燈比沒有測試更糟」的另一種樣子。

**3. ⚠️ `.turnaround-current.json` 不進版控**，所以
⛔ **一輪工作不能在 A 機器 `start`、B 機器 `finish`**。換機器前先收尾。

**4. ✅ 沒有任何秘密要搬。** v0.29 之後沒有資料庫、沒有 `.env`、沒有環境變數。
SSH 金鑰**本來就是每台機器一把**——⛔ 不要複製舊機器的私鑰，
在新機器上重產一把、把公鑰貼到 GitHub（步驟在 `PUBLISHING.md`，Linux 與 macOS 各一份）。

**5. Cowork 那一側**：桌面版、同一個帳號、把 repo **根目錄**接上、
⚠️ **刪檔權限要在那台電腦上現場授權一次**（`git-safe-commit.sh` 會撞到
`.git/objects/**/tmp_obj_*`，而授權對話框出現在那台電腦上）。

**6. 第一次跑測試會是全跑，而那是對的**（理由見上）。⚠️ 沙箱 180 秒上限要分批，
切法在 `CLAUDE.md`——⛔ 不要自己重新發明，那些批是被 180 秒逼出來的。
